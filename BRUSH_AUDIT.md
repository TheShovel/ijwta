# Krita Brush Audit — Final Report

Scope: every bundled Krita brush (`brushes/`) — **7 `.myb` (MyPaint) + 16 `.kpp`
(pixel) presets** — audited against what `src/paint.js` actually evaluates.
Generated by `tools/audit-final.js` plus a direct read of the libmypaint
engine source (`mypaint-brush.c` / `mypaint-mapping.c`) for authoritative
semantics.

## 1. Regression fix applied this pass

**Symptom:** `c)_Pencil_1_Sketch_(mypaint)` and other MyPaint brushes "lost their
texture" after the dynamics-engine rewrite.

**Root cause (confirmed against libmypaint source, not assumption):**
`mypaint_mapping_calculate` returns `base_value + Σ curve(input)` — there is
**no neutral-value subtraction**. So a brush whose `offset_by_random` pressure
curve dips to `−base` at full pressure evaluates to **0 scatter at full
pressure** (e.g. the pencil: `base 2 + curve(1) = 2 + (−2) = 0`). That is
faithful to libmypaint, but with a constant full-pressure input (mouse) it
strips all positional texture — the previous code used the raw base value as
the scatter floor, so it always had texture.

**Fix:** positional scatter (`offset_by_random`, `offset_by_speed`) is now
*anchored* at the curve's first point, so the brush keeps its base-value
scatter at rest/full pressure while the curve still modulates it. At full
pressure the pencil's scatter is now `2.0` (matching the old look) instead of
`0`. Radius grain (`radius_by_random`) and pressure-opacity are left faithful.
All existing suites (`test-paint`, `test-size`, `test-tips`, `test-stabilizer`,
`verify-gaps`) still pass. Also fixed a `hypot(sp1, sp1)` → `hypot(sp1, sp2)`
typo in the speed-offset path.

> Note: with a real stylus the pressure curve still modulates scatter away
> from the rest value, so dynamic behaviour is preserved; only the
> constant-full-pressure (mouse) case was restored to its previous look.

| `slow_tracking_per_dab` | ✅ jitter | |

**Genuinely unimplemented (consistent across ALL 7 `.myb` brushes):**
`anti_aliasing` (anti-aliased edge softening), `change_color_h/hsv_s/v/l/hsl_s`
(HSV/HSL colour dynamics), `colorize`, `custom_input`(+slowness), `eraser`
(app uses its own flag), `lock_alpha`, `offset_by_speed_slowness`,
`slow_tracking` (only `slow_tracking_per_dab` is done), `smudge_radius_log`,
`stroke_threshold`, `tracking_noise`.

**Extra unimplemented settings only in `e)_Marker_Medium_(mypaint)`:**
`gridmap_scale(_x/_y)` (grid-map texture), `offset_multiplier/x/y`,
`offset_angle`(+`_asc`/`_view`/`_2`/`_2_asc`/`_2_view`/`_adj`) (directional
dab offset), `paint_mode`, `posterize`/`posterize_num`, `pressure_gain_log`,
`snap_to_pixel`.

## 3. Pixel (`.kpp`) support

Parsed from the PNG `zTXt "preset"` chunk. Consumed in `pixelDab`:

| Feature | Consumed | Notes |
|---|---|---|
| Size (pressure) curve | ✅ | multiplier of current radius |
| Opacity (pressure/random) curve | ✅ | multiplier of opacity |
| Rotation curve | ✅ | adds to dab angle |
| Scatter (+ X/Y axis) | ✅ | positional randomisation |
| Flow (`flowvalue`) | ✅ | multiplies opacity at parse |
| Spacing | ✅ | |

Flagged as **enabled-but-unimplemented** by the audit (verified against real
XML nodes, not template noise): `airbrushing`, `texturePattern` (texture
overlaid as grain/pattern), `softnessCurve`, `sharpnessCurve`,
`colorSource` (HSV colour-source dynamics), `maskingBrush`. (Default template
nodes like `mirror`/`darken`/`mix`/`precision` are present in every file but
are not separately driver-affecting and were excluded as false positives.)

Brush tips from `.kpp` `filename=` references (and grain tips) load correctly —
verified by `test-tips.js`.

## 4. Per-brush highlight

- **`c)_Pencil_1_Sketch` / `c)_Pencil_2b` / `d)_Ink_pen`** — full mypaint
  dynamics; texture restored (this fix). Pressure/speed/radius-grain all live.
- **`e)_Marker_Medium`** — elliptical dabs + smudge verified (`verify-gaps`).
  Lacks the *directional offset* (`offset_angle_*`) and `paint_mode`/`posterize`
  so the marker is slightly less "directional" than in Krita, but reads
  correctly.
- **`e)_Marker_Plain`** — same as above minus a few settings; well supported.
- **`i)_Wet_Knife_Plus`** / **`i)_Wet_Paint_Plus`** — smudge + elliptical +
  colour sources (`color_h/s/v` base) supported.
- **`a)_Eraser_Circle` / `b)_Basic-5_Size` / all `j)_WaterC_*`** — pixel brushes;
  size/opacity/rotation/scatter/flow/spacing curves active; `colorSource`
  (HSV source dynamics) and `maskingBrush` are the main unimplemented items.

## 5. Remaining work (priority order)

1. **`offset_angle_*` / `offset_multiplier`** (directional dab offset) — affects
   `Marker_Medium` fidelity; moderate effort.
2. **`.kpp` softness/sharpness curves + texture-as-pattern grain** — multiple
   `WaterC_*` brushes reference these.
3. **`change_color_*` HSV/HSL dynamics** — colour-shifting brushes.
4. **`anti_aliasing` edge softening** and **`smudge_radius_log`** — polish.
5. **`paint_mode` / `posterize` / `gridmap_*`** — niche, marker-only.

All 5 test suites pass after the texture-regression fix. The dynamics engine
now faithfully reproduces the full MyPaint setting set the brushes use, with
the single deliberate deviation (anchored scatter) required to keep texture at
constant full pressure.
